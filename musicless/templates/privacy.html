{{ t('Processing, storage & retention') }}

{{ t('Local processing runs on this server, not in your browser.') }}

{{ t('Where processing happens') }}

{{ t('Your browser uploads the selected audio or video to this server. The server validates the file, extracts its audio, runs the installed vocal-separation model, and encodes and checks the result. For video, the video stream is copied and the audio is replaced. “Local” means local to the server, not your device or browser.') }}

{{ t('What is stored') }}

{{ t('While a job runs, the server stores the uploaded file, extracted audio, separated vocals, and output in a job folder. A SQLite database stores the original filename, job and owner identifiers, selected model, file extension, status, processing stage, errors, timestamps, expiry, and cancellation flag. It also stores application settings, worker diagnostics, model availability, and temporary rate-limit records. Media and the database use the configured server data directory; the supplied Docker setup uses persistent host-backed storage.') }}

{{ t('Successful jobs and downloads') }}

{{ t('After successful processing, the worker deletes the uploaded source and intermediate files, keeping only the output. The configured output retention is {retention} seconds from completion. Downloads are refused once that expiry is reached. Downloading does not delete the output or extend its expiry. Files you download to your own device remain under your control.', retention=retention) }}

{{ t('Failures, cancellation, and cleanup') }}

{{ t('Failed, cancelled, and expired job folders are removed during cleanup. Cleanup runs roughly every 30 seconds while the worker is running, and after a running job finishes. Uploads with no recorded progress for 20 minutes and queued jobs older than one hour are marked failed during cleanup. The configured processing timeout is {timeout} seconds. Cleanup can be delayed by worker downtime, long operations, or deletion failures; expiry is not a guarantee of immediate physical deletion. There is a cancel action for queued or processing jobs, but no user-facing delete action for completed jobs.', timeout=timeout) }}

{{ t('How long job records remain') }}

{{ t('Job metadata is separate from media files. During cleanup, failed, cancelled, or expired database records are deleted when their last update is more than 24 hours old. For a successful job, expiry does not reset that timestamp, and its record is only eligible for deletion after the output expires. Settings and stored worker diagnostics have no automatic retention limit. Rate-limit records can include an IP address, visitor identifier, or administrator username; old records are pruned on later requests using the applicable 60-second or 300-second window, rather than by a background timer.') }}

{{ t('Browser session and access') }}

{{ t('A signed session cookie holds a random visitor identifier, a CSRF protection token, your language preference, and administrator identity when signed in. The session lifetime is eight hours and can be refreshed by activity. Arabic is the default language. This application does not store your media in browser local storage. Guest jobs are accessible through the originating visitor session; administrator jobs use the signed-in username. Clearing or losing the cookie may prevent access to guest jobs, but does not delete their files. The server operator can access the underlying storage.') }}

{{ t('External services and model use') }}

{{ t('The application processes media with installed models and does not send it to an external AI API. Runtime model downloads are disabled. The supplied Docker worker has no network access, and the worker also blocks Python network connections. Files are used for separation, not for model training by this application. These statements describe this application and its supplied deployment, not independent services an operator may add.') }}

{{ t('Logs, backups, and deletion limits') }}

{{ t('Worker error logs may contain job identifiers, paths, and diagnostic details. Web-server or reverse-proxy logs may also contain request details, including filenames in upload URLs. This application does not define retention for infrastructure logs or backups, and does not implement backup cleanup or secure erasure of deleted data. The database and media are not encrypted by the application at rest. Contact the server operator for deployment-specific logging, backup, encryption, or deletion policies.') }}
